# 🌍 여행지 추천 프로그램

Gemini AI와 카카오 API를 활용해 날짜를 입력하면
여행지, 날씨, 이벤트, 맛집을 추천해주는 CLI 프로그램입니다.

## 📖 개요
- **Gemini API**: 추천 도시 / 날씨 / 이벤트 / 추천 이유 제공
- **카카오 로컬 API**: 추천 도시의 맛집 검색
- 결과를 **JSON**과 **Markdown 리포트**로 저장

## 🛠️ 설치 방법
```bash
# 1. 저장소 클론
git clone <저장소 URL>
cd <프로젝트 폴더>

# 2. 라이브러리 설치
pip install -r requirements.txt
```

## 🔑 API 키 설정
프로젝트 루트에 `.env` 파일을 만들고 아래처럼 입력하세요:

```
GEMINI_API_KEY=여기에_본인_키
KAKAO_API_KEY=여기에_본인_키
```

- Gemini 키 발급: https://ai.google.dev/
- 카카오 키 발급: https://developers.kakao.com/

## ▶️ 실행 방법
```bash
python main.py --date 2026-01-01
```
- `--date`: 여행 날짜 (형식: `YYYY-MM-DD`)

## 📂 결과물 확인
실행 후 `results/` 폴더에 저장됩니다:
- `travel_2026-01-01.json` : 원본 데이터
- `travel_2026-01-01.md` : 읽기 좋은 리포트

## ⚠️ 주의사항 (API 키 보안)
- **`.env` 파일은 절대 깃허브에 올리지 마세요!**
- `.gitignore`에 `.env`를 반드시 추가하세요.
- API 키가 코드에 직접 노출되지 않도록 주의하세요.
- 키가 유출되면 즉시 재발급하세요.

## API 호출에서 발생하는 오류와 대응 원칙
API 호출 중 오류(401, 403 등)가 발생하면 터미널에 **'Gemini API 호출 중 오류 발생!'**이라는 메시지와 함께 상세 원인이 출력됩니다. 이를 통해 API 키 유효성이나 권한 설정을 즉시 확인할 수 있습니다.
| 오류 | 원인 | 대응 |
|---|---|---|
| 인증(401/403) | 키 잘못됨 | 키 확인/재발급 |
| 쿼터(429) | 요청 초과 | 잠시 후 재시도 |
| 네트워크(503) | 서버 과부하 | 대기 후 재시도 |
| 파싱 | JSON 형식 깨짐 | 검증/재요청 |

## 🛠 기술 결정 (HTTP Methods)

본 프로젝트에서는 카카오 로컬 API와의 통신을 위해 HTTP GET 방식을 사용했습니다.

### 1. GET vs POST 선택 이유
- **GET**: 서버에서 데이터를 조회할 때 사용합니다. 본 프로젝트의 '맛집 검색'은 데이터를 변경하지 않고 정보를 가져오기만 하므로 GET 방식이 적합합니다.
- **POST**: 서버에 데이터를 생성하거나 변경할 때 사용합니다. (예: 리뷰 작성, 회원 가입 등)

### 2. 사용된 API 엔드포인트 예시
- **맛집 검색 (GET)**: `https://dapi.kakao.com/v2/local/search/keyword.json`
  - 목적: 키워드를 기반으로 장소 정보를 조회
  - 파라미터: `query`, `category_group_code` 등을 URL에 포함하여 전달
 
## 🤖 LLM 응답 구조화 설계

본 프로젝트에서는 Gemini API의 응답을 반드시 **JSON 형식**으로 출력하도록 강제하였습니다. 그 이유는 다음과 같습니다.

1. **파싱 자동화**: 자유 형식의 텍스트 대신 구조화된 JSON을 사용함으로써, 별도의 복잡한 문자열 처리 없이 `json` 라이브러리를 통해 데이터를 즉시 객체화할 수 있습니다.
2. **데이터 무결성 검증**: 추천 도시, 날씨, 이벤트 등 필요한 정보가 누락되지 않았는지 프로그래밍적으로 검증이 가능합니다.
3. **워크플로우 연결(Pipeline)**: Gemini가 추천한 '도시명'을 추출하여 즉시 카카오 맛집 검색 API의 입력값으로 전달하는 등, 기능 간의 데이터 흐름을 자동화하기 위해 일관된 데이터 규격이 필수적입니다.
4. **에러 핸들링**: JSON 파싱 실패 시 재시도(Retry) 로직을 수행함으로써 LLM의 비결정적 특성(불규칙한 답변)으로 인한 프로그램 중단을 방지합니다.

## 💾 캐싱 전략 (Caching Strategy)

본 프로젝트는 API 호출 비용 절감과 응답 속도 향상을 위해 캐싱 로직을 적용했습니다.

1. **저장 방식**: `results/` 디렉토리에 `recommendation_{date}.json` 형식으로 저장
2. **재사용 로직**:
   - 프로그램 실행 시 입력된 날짜와 일치하는 파일이 있는지 확인합니다.
   - 파일이 존재할 경우, API 호출을 생략하고 로컬 데이터를 즉시 반환합니다.
3. **캐시 무효화(Invalidation)**:
   - 최신 정보가 필요할 경우 `results/` 폴더 내의 해당 JSON 파일을 삭제 후 재실행하면 API를 통해 새로운 데이터를 가져옵니다.

입력값 검증: 날짜 형식이 올바르지 않으면 사용법을 출력하고 종료한다.

<인증/요청 최소 가이드>
Kakao Local 예시: 인증 헤더에 키를 실어 요청하는 방식(401/403 발생 시 키/권한/도메인 설정을 점검)
Naver Local Search 예시: 클라이언트 ID/Secret을 헤더로 보내는 방식(401/403 발생 시 키 값/헤더명 오타를 점검)

<에러 처리>
try-except로 API 호출/파싱 오류를 처리한다.
최소 정책
API 키 미설정: 즉시 종료 + 설정 방법 안내 출력

LLM JSON 파싱 실패: 재요청 1회 또는 “필수 키만 다시 JSON으로 출력”하도록 프롬프트를 수정해 재시도 1회
